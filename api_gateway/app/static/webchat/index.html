Integración

Cómo agregarlo a tu página

Tres pasos: cargar el CSS y el JS del widget, definir la configuración antes de que el script corra, y listo — se auto-inicializa solo.

1

Cargá el CSS y el script del widget

Van en cualquier parte de tu <head> o antes de cerrar </body>. Se sirven desde nuestro dominio, no hace falta alojarlos vos.

<link rel="stylesheet" href="https://chat.flowsdone.com/agent-chat-widget.css" />
<script src="https://chat.flowsdone.com/agent-chat-widget.js"></script>
2

Definí window.AgentChatConfig antes del script

El widget busca esta variable global apenas carga y se auto-inicializa. El único campo obligatorio es workflowId: sin él, no hay a dónde enviar los mensajes.

<script>
  window.AgentChatConfig = {
    workflowId: "TU_WORKFLOW_ID",   // obligatorio
    transport: "kafka",             // "kafka" (Langflow) o "rabbitmq" (n8n)
    title: "Mi Asistente",
    initialMessage: "¡Hola! ¿En qué te puedo ayudar?",
    launcherColor: "#4F46E5",
    sendButtonColor: "#10B981"
  };
</script>
<link rel="stylesheet" href="https://chat.flowsdone.com/agent-chat-widget.css" />
<script src="https://chat.flowsdone.com/agent-chat-widget.js"></script>
3

(Opcional) Inicializá manualmente

Si preferís no usar window.AgentChatConfig — por ejemplo, para crear el widget después de una acción del usuario — llamá a init() a mano con el script cargado con defer.

<script defer src="https://chat.flowsdone.com/agent-chat-widget.js"></script>
<script>
  window.addEventListener("load", function () {
    window.AgentChat.init({ workflowId: "TU_WORKFLOW_ID", transport: "kafka" });
  });
</script>
Referencia

Variables de configuración disponibles

Todo lo que acepta AgentChatConfig / AgentChat.init(options), agrupado por para qué sirve. Ninguna es obligatoria salvo workflowId.

Conexión

VariableDefaultQué hace
workflowId—Obligatorio. El workflow (Langflow o n8n) al que se enrutan los mensajes.
transportrabbitmqkafka para Langflow, rabbitmq para n8n. Define el camino que toma el mensaje dentro del gateway.
wsUrlautoEndpoint del WebSocket. Por defecto se arma solo a partir del dominio actual (wss://tu-dominio/ws) — normalmente no hace falta tocarlo.
sessionIdautoId de sesión del visitante. Se genera y persiste en localStorage si no lo pasás.
conversationIdautoId de conversación, también persistido en localStorage. Pasalo vos si necesitás controlar cuándo empieza una conversación nueva.
userId—Identificador del usuario que envía los mensajes (para trazabilidad del lado del workflow).
